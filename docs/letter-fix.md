# 来信详情白屏 · 修复版 1.2.1

## 查到的原因

线上首页文件与之前提供的 1.2.0 新版前端 SHA-256 完全一致。但是，正式网址的公开投票接口返回 `{"polls":[]}`，没有新版接口必带的 `hasMore` 和 `server_now` 字段。这表明当前正式路径调用的后端仍是旧版接口。

你已经上传过前端和云函数两个包，因此不能把原因归结为“忘记上传云函数”。还需要确认上传之后代码是否已部署生效、是否更新了正确的环境与函数，以及正式 `/bridge-api` 路径是否关联到了这一版本。

旧版 `GET staff?id=...` 忽略详情参数，仍返回来信列表；新版前端原本把它当成单封来信读取，遇到不存在的 `status` 后调用 `.split()`，使 React 页面崩溃。使用隔离的旧版接口已复现完全相同的白屏和错误：`Cannot read properties of undefined (reading 'split')`。

旧版/异常响应进入页面前缺少检查，也是本次前端需要修复的问题。现已加入详情格式校验：版本不匹配时保留列表、导航并显示明确提示；异常详情也不会进入渲染状态。学生查信和追加内容使用相同保护。

没有读取真实来信、使用你的登录凭据、修改生产数据或替换正式网站。上述复现只用了本地测试记录。

## 现在怎么更新

本目录的前端、云函数和源码 ZIP 已统一更新为 **1.2.1**，请重新取用这里的包，不要继续使用之前下载到“下载”文件夹里的旧副本。

### 1. 重新部署现有 bridge-api

进入环境 **`idhssses-d7gtdzl4f86a805c9`** 中的现有 **`bridge-api`** 云函数，上传 **`02-THE-BRIDGE-云函数-1.2.1.zip`**，完成保存和部署。

- 压缩包根目录直接包含 `index.js`、`core.js`、`store.js` 等文件，不嵌套第二层文件夹。
- 入口仍为 `index.main`。
- 保留现有运行环境、环境变量、数据库配置和 HTTP 路径。
- 不需要执行 SQL、初始化数据库或更改账号密码。

### 2. 先确认正式接口确实变成了新版

打开这个公开检查地址：

[检查正式后台版本](https://idhssses-d7gtdzl4f86a805c9-1508185821.ap-shanghai.app.tcloudbase.com/bridge-api?route=health)

成功后应看到 JSON 中有下面两个字段：

```json
"api_version": 2,
"release": "1.2.1"
```

**只出现 `ok: true` 不代表更新成功，必须看到 `release: "1.2.1"`。**

如果仍没有版本字段，可以在云函数控制台测试同一函数，测试事件使用：

```json
{
  "httpMethod": "GET",
  "queryStringParameters": {"route": "health"},
  "headers": {}
}
```

查看返回结果 `body` 里的版本号：

- **控制台测试和网址都没有 1.2.1**：检查当前环境、函数名称和刚上传的代码，确认已保存并部署成功。新版 `core.js` 中包含 `release:'1.2.1'`。
- **控制台测试有 1.2.1，正式网址没有**：检查现有 HTTP 访问服务/网关中 `/bridge-api` 的关联函数，以及所使用的版本或别名，确保它调用刚部署的 `bridge-api`。保留原来的公开域名和路径。

这一步能区分“代码没有生效”和“正式路径调用了其他版本”，无需猜测，也不需要动数据库。

### 3. 再更新前端

解压 **`01-THE-BRIDGE-前端-1.2.1.zip`**，将 `index.html`、`thebridge.idhs.html`、`bridge-config.js` 和完整 `assets/` 覆盖上传到原来的 **`idhs/`**。

打开原工作人员页面，按 **Ctrl + F5** 强制刷新，再进入 THE VOICE 点击一封待回复信件和一封已回复信件。两种情况都应出现正文与历史记录。若后端仍旧，修复后的前端会显示版本提示，而不是白屏。

## 验证结果

- 新后端：未回复的旧记录可打开，并可连续追加两封回信；已有旧回复的信件显示完整原文与回复。
